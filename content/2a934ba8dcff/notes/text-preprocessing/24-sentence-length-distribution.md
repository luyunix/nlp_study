## 零基础精讲：把这一节慢下来

### 先看一个具体场景

99% 的评论不超过 80 个 token，只有一条粘贴了整篇说明书、长度 5000。若按最大值补齐，每条普通评论都会浪费大量空位置。

### 数据究竟怎样一步步变化

1. 用模型实际 tokenizer 计算每条长度
2. 画直方图并查看 95/99 分位
3. 抽查长尾样本是否异常
4. 结合显存和验证效果选择目标长度

把上面四步和流程图对照起来：

> 计算每条长度 → 直方图/分位数 → 检查长尾 → 选择目标长度

这里的箭头表示“左边的数据经过一次处理，变成右边的数据”，不是四个需要孤立背诵的名词。

## 真正看懂这节：为什么不能直接把最大句长设成模型长度

仍用售后文本。先明确“长度”的口径：

```text
原文：包装破损，申请换货
字符长度：可能按汉字与标点计数
分词后：包装 / 破损 / 申请 / 换货
token 长度：4
```

模型处理的是 token ID，所以选择 padding/truncation 长度时，通常统计与最终 tokenizer 完全一致的 token 数。不能前面按字符统计，后面却按子词模型训练。

### 从一串长度到分布图

假设训练集长度是：

```text
[2, 3, 3, 4, 4, 5, 6, 8, 12, 40]
```

```mermaid
flowchart LR
    A["每条分词文本"] --> B["len(tokens)"]
    B --> C["长度序列<br/>2,3,3,4…40"]
    C --> D["直方图 + 分位数"]
    D --> E["选择候选长度 L"]
```

`40` 是一个很长的样本。若直接取最大值 `L=40`，其他 9 条大部分都要补很多 PAD，计算浪费。若取 `L=8`，前 8 条完整保留，后两条被截断。这里没有免费的选择：覆盖率与计算成本必须交换。

### 直方图和 KDE 各告诉你什么

- 直方图：每个长度区间真实落入多少样本；
- KDE：对分布形状做平滑估计，帮助看峰和尾部，但不是原始计数。

小数据时 KDE 可能画出看似平滑、实则不可靠的曲线，因此必须同时看直方图与真实分位数。课程里的旧 `distplot` 已逐渐被更明确的 `histplot`/`kdeplot` 替代，核心思想不变。

### 平均数为什么不够

上面长度的平均数会被 `40` 明显拉高，但中位数仍接近 4–5。更有用的是：

| 统计量 | 回答的问题 |
|---|---|
| 中位数 P50 | 一半样本不超过多长 |
| P90 | 90% 样本不超过多长 |
| P95/P99 | 尾部样本要覆盖到什么程度 |
| 最大值 | 最极端样本多长，是否异常 |

```python
import numpy as np

lengths = np.array([2, 3, 3, 4, 4, 5, 6, 8, 12, 40])
print(np.quantile(lengths, [0.5, 0.9, 0.95, 0.99]))
```

### 候选长度怎样真正决定

```mermaid
flowchart TB
    A["训练集 token 长度分布"] --> B["候选 L：8 / 12 / 16"]
    B --> C["覆盖率<br/>有多少样本不截断"]
    B --> D["计算与显存成本"]
    B --> E["下游验证指标"]
    C --> F["选择可接受交换"]
    D --> F
    E --> F
```

不要用测试集反复挑 `L`，否则测试信息参与了模型决策。合理流程是用训练集统计提出候选，在验证集比较效果，测试集只做最终一次评估。

### 一个极长样本不等于脏数据

它可能是：

- 真实的长投诉；
- 多条记录误拼接；
- HTML/日志没有清理；
- 分词器异常；
- 合法但非常少见的尾部样本。

先回看原文，再决定清理、分段、保留或截断。仅凭散点离群就删除，会丢掉业务中最复杂的案例。

## 最小可运行代码

在项目根目录运行下面代码。课程原理的标准库版本集中在 [text_preprocessing_from_scratch](../../text_preprocessing_from_scratch/README.md)；需要 jieba、PyTorch、FastText 等的示例，请先按代码注释安装依赖。

```python
lengths = [5, 8, 8, 10, 12, 13, 20, 100]
lengths = sorted(lengths)
def percentile(p):
    i = round((len(lengths) - 1) * p)
    return lengths[i]
print("中位数", percentile(0.5))
print("约95分位", percentile(0.95))
```

### 输入和输出怎么看

少数 100 的长文本不会迫使所有样本都补到 100；可结合 95/99 分位与任务损失选择长度。

## 最容易踩的坑

用 Python len(中文字符串) 得到字符数，不是 jieba 词数，更不是模型 tokenizer 的子词数。
